# B 爬山：从普通最短路到状态扩展 Dijkstra

- [题目链接](https://qoj.ac/contest/2564/problem/14451)
- [对应代码](../../ccpc_women_2025/B_爬山.cpp)
- 关键词：`状态扩展`、`分层图`、`Dijkstra`、`最短路`

## 核心思考链

这道题最值得记住的不是“看到题目就写二维 Dijkstra”，而是下面这条推导过程：

```text
要求最短时间
↓
先尝试普通 Dijkstra
↓
发现 dist[u] 不能完整描述当前情况
↓
到达 u 时的累计爬升不同，后续合法转移也不同
↓
把累计爬升加入状态
↓
状态变为 (u, hh)
↓
扩展状态图中的边权仍是非负时间
↓
在扩展状态图上运行 Dijkstra
```

一句话口诀：

> 未来决策依赖什么，状态里就要记录什么。

## 第一步：先按普通最短路思考

题目给出点、边、非负时间，并要求最短时间，因此第一反应自然是定义：

```cpp
dist[u]
```

表示到达节点 `u` 的最短时间，再使用 Dijkstra。

普通最短路只记录当前位置，是因为无论以什么方式到达 `u`，到达之后可以走的边都完全相同。过去的经历不会影响未来决策，所以在同一个点只需保留时间最短的方案。

## 第二步：检查“同一点的未来是否完全相同”

考虑两个到达同一节点 `u` 的方案：

```text
方案 1：时间为 5，当前累计爬升为 9
方案 2：时间为 7，当前累计爬升为 2
```

假设累计爬升上限 `H = 10`，下一条边需要继续上升 `4`：

```text
方案 1：9 + 4 > 10，不能走
方案 2：2 + 4 <= 10，可以走
```

虽然方案 1 更早到达 `u`，但它不能代替方案 2，因为两种方案后续可走的边不同。也就是说，当前位置相同并不代表它们是同一个完整状态。

这时普通的：

```cpp
dist[u]
```

已经不够用了。

## 第三步：找出缺失的信息

判断下一条边能否行走，除了当前位置 `u`，还依赖当前累计爬升 `hh`。因此定义：

```cpp
dp[u][hh]
```

表示到达节点 `u`，且当前累计爬升为 `hh` 时的最短时间。

可以把原图中的一个节点 `u` 想象成被拆成 `H + 1` 个状态节点：

```text
(u, 0), (u, 1), (u, 2), ..., (u, H)
```

因此问题本质上仍然是最短路，只是从原图变成了扩展状态图（也可理解为分层图）。

## 第四步：设计状态转移

当前状态为：

```text
(u, hh)
```

沿时间为 `t` 的边走向 `v`。

### 下坡

当：

```cpp
h[u] > h[v]
```

累计爬升清零：

```cpp
nh = 0;
```

状态转移为：

```text
(u, hh) --t--> (v, 0)
```

### 平路或上坡

新的累计爬升为：

```cpp
nh = hh + h[v] - h[u];
```

只有满足：

```cpp
nh <= H
```

才能转移：

```text
(u, hh) --t--> (v, nh)
```

## 第五步：在扩展状态图上跑 Dijkstra

扩展图中每条边的权值仍是原边所需的时间 `t`，且边权非负，所以使用 Dijkstra：

```cpp
vector<vector<long long>> dp(n + 1, vector<long long>(H + 1, INF));
priority_queue<State> pq;

dp[1][0] = 0;
pq.push({1, 0, 0});
```

松弛的对象不再只是节点 `v`，而是完整状态 `(v, nh)`：

```cpp
if (dp[v][nh] > dp[u][hh] + t) {
    dp[v][nh] = dp[u][hh] + t;
    pq.push({v, dp[v][nh], nh});
}
```

到达节点 `u` 的最终答案，是所有累计爬升状态中的最小值：

```cpp
ans[u] = *min_element(dp[u].begin(), dp[u].end());
```

## 为什么不能只保留最短时间

Dijkstra 可以淘汰“同一状态下距离更大”的方案，但这里的“同一状态”必须是完整的 `(u, hh)`，而不能只有 `u`。

```text
到达时间更短但累计爬升更高
```

与：

```text
到达时间更长但累计爬升更低
```

之间不存在简单的替代关系。前者时间占优，后者可能拥有更多可行的后续路线，所以两者都可能需要保留。

## 通用判断方法

做最短路题时，问自己：

> 到达同一个节点后，不同的历史经历会不会导致后续能做的事情不同？

如果答案是“会”，普通 `dist[u]` 往往不够，需要把影响未来决策的信息加入状态。常见形式有：

```text
dist[u][剩余油量]
dist[u][免费机会使用次数]
dist[u][钥匙状态]
dist[u][当前颜色]
dist[u][剩余体力]
dist[u][累计高度]
dist[u][mask]
```

判断的重点不是“是否存在额外变量”，而是这个变量是否会影响未来的合法转移或转移代价。

## 复杂度

扩展状态数最多为：

```text
O(nH)
```

每条原图边可能在不同累计爬升状态下被处理，因此转移规模最多为 `O(mH)`。使用 Dijkstra 后，时间复杂度可写为：

```text
O(mH log(nH))
```

距离数组与原图邻接表占用 `O(nH + m)` 空间；计入优先队列后，最坏空间复杂度为：

```text
O(nH + mH)
```

## 脑内模板

```text
1. 题目要求最短代价，先考虑普通最短路。

2. 检查仅用节点 u 能否决定未来的所有转移。

3. 如果不能，找出影响未来合法性或代价的最小附加信息 s。

4. 将状态扩展为 (u, s)，定义 dist[u][s]。

5. 根据题意写出 (u, s) 到 (v, ns) 的转移。

6. 根据扩展图的边权选择 BFS、0-1 BFS 或 Dijkstra。

7. 最终答案通常是所有终点附加状态中的最优值。
```

一句话总结：

> 当“到达同一个点”不足以保证“未来完全相同”时，就把影响未来的信息加入状态，再在扩展状态图上求最短路。
