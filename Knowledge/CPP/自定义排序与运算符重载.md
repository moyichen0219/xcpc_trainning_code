# C++ 自定义排序与运算符重载

- 关键词：`std::sort`、`lambda`、`operator<`、`比较器`、`升序`、`降序`

## 核心规则

`std::sort` 的比较器回答的是：

> `A` 是否应该排在 `B` 前面？

返回 `true`，表示 `A` 应排在 `B` 前面；返回 `false`，表示不要求 `A` 排在 `B` 前面。

因此：

- 从小到大使用 `<`；
- 从大到小使用 `>`。

例如，要求 `x` 从小到大，`x` 相同时 `y` 从大到小：

```cpp
if (A.x != B.x) {
    return A.x < B.x;
}
return A.y > B.y;
```

可以把它直接理解为：先按 `x` 升序比较；只有 `x` 相等时，才按 `y` 降序比较。

## 方法一：lambda 表达式

```cpp
sort(a.begin(), a.end(), [](const Node& A, const Node& B) {
    if (A.x != B.x) {
        return A.x < B.x;
    }
    return A.y > B.y;
});
```

这是做题时通常最方便的写法。排序规则直接写在 `sort` 附近，一眼就能看到每个关键字是升序还是降序，也不会改变 `Node` 在其他地方的默认顺序。

适合：

- 排序规则只使用一两次；
- 同一种结构体需要多种排序方式；
- 希望排序逻辑紧挨着调用位置，便于阅读。

同一个 `Node` 可以轻松使用不同规则：

```cpp
// x 升序，x 相同时 y 降序
sort(a.begin(), a.end(), [](const Node& A, const Node& B) {
    if (A.x != B.x) return A.x < B.x;
    return A.y > B.y;
});

// y 升序，y 相同时 x 升序
sort(a.begin(), a.end(), [](const Node& A, const Node& B) {
    if (A.y != B.y) return A.y < B.y;
    return A.x < B.x;
});
```

## 方法二：在结构体内重载 `operator<`

更准确的说法是“重载运算符”，不是“重构运算符”。

```cpp
struct Node {
    int x, y;

    bool operator<(const Node& other) const {
        if (x != other.x) {
            return x < other.x;       // x 从小到大
        }
        return y > other.y;           // x 相同时，y 从大到小
    }
};
```

定义后可以直接排序：

```cpp
sort(a.begin(), a.end());
```

这里有两个 `const`：

```cpp
bool operator<(const Node& other) const
//             ^ 不修改 other       ^ 不修改当前对象
```

这种写法相当于为 `Node` 定义了一个固定的“默认顺序”。它也能直接用于依赖 `<` 的有序容器，例如 `set<Node>` 和 `map<Node, ...>`。

适合：

- 这种排序规则是结构体最自然、最常用的默认顺序；
- 很多地方都要使用完全相同的比较规则；
- 希望直接调用 `sort(a.begin(), a.end())`。

如果同一结构体经常需要多种排序规则，通常优先使用 lambda，避免把某一种临时规则固定成默认顺序。

## 方法三：普通比较函数

```cpp
bool cmp(const Node& A, const Node& B) {
    if (A.x != B.x) {
        return A.x < B.x;
    }
    return A.y > B.y;
}

sort(a.begin(), a.end(), cmp);
```

它与 lambda 的逻辑相同，只是把比较规则单独命名。适合多个位置复用同一种规则，或者比较逻辑较长、希望单独阅读和调试的情况。

## 方法四：函数对象

```cpp
struct CompareNode {
    bool operator()(const Node& A, const Node& B) const {
        if (A.x != B.x) {
            return A.x < B.x;
        }
        return A.y > B.y;
    }
};

sort(a.begin(), a.end(), CompareNode{});
```

函数对象把比较规则封装成一个类型，适合复用，也常用于需要显式指定比较器类型的容器：

```cpp
set<Node, CompareNode> s;
priority_queue<Node, vector<Node>, CompareNode> q;
```

注意：`priority_queue` 的比较器语义容易和 `sort` 混淆。上面这个比较器会让“按该规则更靠后”的元素位于队首，使用时应结合题目单独确认堆顶元素。

## 方法五：使用 `tuple` 简化多关键字排序

当字段都是普通数值，并且可以安全取相反数时，可以利用 `tuple` 的字典序比较：

```cpp
sort(a.begin(), a.end(), [](const Node& A, const Node& B) {
    return tuple{A.x, -A.y} < tuple{B.x, -B.y};
});
```

`x` 原样放入元组，所以按升序排列；`y` 取相反数后按升序比较，效果等价于让原来的 `y` 降序排列。

不过这种写法要留意整数最小值取相反数可能溢出。竞赛中更稳妥、更直观的写法仍然是逐项判断。

如果所有关键字都是升序，可以直接使用：

```cpp
return tie(A.x, A.y) < tie(B.x, B.y);
```

## 常见错误

### 1. 使用 `<=` 或 `>=`

错误示例：

```cpp
return A.x <= B.x;
```

当 `A.x == B.x` 时，`cmp(A, B)` 和 `cmp(B, A)` 都会返回 `true`，破坏 `std::sort` 要求的严格弱序，可能产生未定义行为。

比较器应该使用严格比较 `<` 或 `>`。相等元素之间应返回 `false`。

### 2. 多个条件互相矛盾

不要写成：

```cpp
return A.x < B.x || A.y > B.y;
```

例如 `A.x < B.x`，但 `B.y > A.y` 时，可能同时得到 `cmp(A, B) == true` 和 `cmp(B, A) == true`。多关键字排序应先判断第一关键字是否不同，相同时再比较下一关键字。

### 3. 忘记引用和 `const`

推荐参数写成：

```cpp
const Node& A, const Node& B
```

这样既不会复制对象，也保证比较过程不会修改对象。

### 4. 误以为 `operator<` 只能表示所有字段升序

`operator<` 的含义是定义对象的默认先后关系，不要求每个字段都使用 `<`。因此下面的混合顺序完全合法：

```cpp
if (x != other.x) return x < other.x; // x 升序
return y > other.y;                   // y 降序
```

## 选择建议

| 方法 | 主要特点 | 推荐场景 |
| --- | --- | --- |
| lambda | 规则就在调用处，修改方便 | 做题首选、临时规则、多种排序方式 |
| 重载 `operator<` | 定义结构体的默认顺序 | 全局统一且频繁使用的规则 |
| 普通函数 | 有名字，便于复用和调试 | 多处使用同一种较长规则 |
| 函数对象 | 比较器本身是一个类型 | `set`、`priority_queue` 等容器 |
| `tuple` / `tie` | 多关键字写法简洁 | 全升序，或能安全转换的简单字段 |

## 脑内模板

最推荐记住 lambda 版本：

```cpp
sort(a.begin(), a.end(), [](const Node& A, const Node& B) {
    if (A.x != B.x) return A.x < B.x; // 第一关键字：升序
    return A.y > B.y;                 // 第二关键字：降序
});
```

判断符号时只问一句：

> 当只看当前关键字时，`A` 满足什么条件才应该站在 `B` 前面？

- 值小的站前面：写 `<`；
- 值大的站前面：写 `>`。
