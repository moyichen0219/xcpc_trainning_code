# P1197 星球大战：离线逆序与并查集

- [题目链接](https://www.luogu.com.cn/problem/P1197)
- [对应代码](../../LuoGu/P1197_星球大战.cpp)
- 关键词：`并查集`、`离线算法`、`逆序处理`、`动态连通性`

## 核心思想

这道题不是单纯考并查集，而是在考一个非常重要的算法思想：

> 遇到难以处理的删除操作，考虑离线 + 逆序，把删除变成添加。

并查集擅长合并两个集合，却无法轻易把一个集合拆开。例如：

```text
0 -- 1 -- 2
```

删除点 `1` 后，一个连通块会裂成两个：

```text
0     2
```

普通并查集不知道应该如何完成这种“拆分”。但题目提前给出了全部删除操作，因此可以先构造所有攻击结束后的图，再倒序恢复被删除的点。这样，正向的删点就转换成了并查集擅长的加点与合并。

```text
正向删除难维护
      ↓
所有操作提前已知
      ↓
离线并逆序处理
      ↓
删除转换成添加
```

## 知识点一：离线算法

如果题目的全部询问或修改操作可以提前知道，就不一定要按照输入顺序实时处理。先读入所有操作，再统一安排计算顺序，这种方式叫离线处理。

原操作顺序：

```text
删除 A → 删除 B → 删除 C → 删除 D
```

逆序处理：

```text
假设 A、B、C、D 已全部删除
恢复 D → 恢复 C → 恢复 B → 恢复 A
```

计算顺序可以和题目给出的操作顺序不同，只要最后把答案映射回正确顺序即可。

## 知识点二：删点转换为逆序加点

状态数组记录一个点当前是否存在：

```cpp
bool attacked[N];
```

- `attacked[x] == true`：点 `x` 当前已被删除；
- `attacked[x] == false`：点 `x` 当前存在。

逆序恢复一个点：

```cpp
attacked[del[i]] = false;
cnt++;
```

恢复后先执行 `cnt++`，因为这个点刚出现且尚未与其他点合并时，本身就是一个新的独立连通块。随后遍历它的邻居，只与当前存在的邻居尝试合并。

```cpp
for (int v : g[del[i]]) {
    if (!attacked[v]) {
        // 尝试合并 del[i] 和 v
    }
}
```

## 知识点三：动态维护连通块数量

不需要在每次操作后重新用 DFS 或 BFS 统计连通块，只需维护：

```cpp
int cnt;
```

它始终表示当前图中的连通块数量。变化规律只有两条：

```text
加入一个新点                 → cnt + 1
合并两个原本不同的连通块     → cnt - 1
```

“原本不同”非常重要。如果两个点已经连通，再加入它们之间的边不会改变连通块数量。

```cpp
if (root(u) != root(v)) {
    merge(u, v);
    cnt--;
}
```

因此，连通块数量减少的条件不是“处理了一条边”，而是“这条边连接了两个原本不同的连通块”。

## 知识点四：状态数组

`attacked` 本质上是一个以点编号为下标的状态数组，可以在 `O(1)` 时间内判断某个点当前是否存在。

类似设计还常写成：

```cpp
bool alive[N];
bool active[N];
bool deleted[N];
bool vis[N];
bool used[N];
```

它们的共同作用是用编号直接记录和查询元素状态，比每次在线性容器中搜索高效得多。

## 知识点五：答案顺序映射

实际计算顺序是：

```text
所有攻击之后 → 恢复最后一个点 → ... → 恢复第一个点
```

题目要求的输出顺序却是：

```text
初始状态 → 第一次攻击后 → ... → 所有攻击之后
```

因此可以按计算顺序存入答案：

```cpp
ans.push_back(cnt);
```

最后倒序输出：

```cpp
for (int i = static_cast<int>(ans.size()) - 1; i >= 0; i--) {
    cout << ans[i] << '\n';
}
```

这说明计算顺序不必强行与输出顺序一致。应优先选择容易维护的计算顺序，最后再调整答案顺序。

## 并查集写法优化

如果先调用 `isConnect()`，再调用 `merge()`，会重复执行 `root()`。更推荐让合并函数直接返回是否真正发生了合并：

```cpp
int root(int u) {
    return pre[u] == u ? u : pre[u] = root(pre[u]);
}

bool merge(int u, int v) {
    int rtu = root(u);
    int rtv = root(v);

    if (rtu == rtv) {
        return false;
    }

    pre[rtu] = rtv;
    return true;
}
```

使用时直接写：

```cpp
if (merge(u, v)) {
    cnt--;
}
```

恢复点时同理：

```cpp
for (int v : g[del[i]]) {
    if (!attacked[v] && merge(del[i], v)) {
        cnt--;
    }
}
```

逻辑可以直接理解为：合并成功，两个连通块变成一个，所以 `cnt--`。

## 可迁移思想

### 多次删点并查询连通性

优先考虑：

```text
离线 + 逆序恢复 + 并查集
```

### 多次删边并查询连通性

先移除最终会被删除的全部边，再逆序加边。每加入一条连接不同连通块的边，就合并集合并令 `cnt--`。

```text
删点问题 → 逆序加点
删边问题 → 逆序加边
```

### 难维护的操作能否倒过来做

这个思想不局限于并查集。看到“删除复杂、添加简单，并且全部操作提前已知”时，都应考虑能否离线逆序处理。

## 并查集的常见应用

当问题需要反复判断两个元素是否属于同一组，或者持续合并集合时，可以考虑并查集，例如：

- 图的连通性；
- 朋友或帮派关系；
- 道路和网络连接；
- 岛屿合并；
- Kruskal 最小生成树。

并查集的两个核心操作是：

```text
find/root：查询元素属于哪个集合
merge：合并两个集合
```

## 脑内模板

```text
题目：不断删除点，并询问连通块数量

普通并查集只会合并，不会拆分
因此采用离线 + 逆序：

1. 标记所有将被删除的点。

2. 建立所有删除操作结束后的图：
   cnt = 剩余点数；
   合并剩余点之间的边；
   每次有效合并，cnt--。

3. 从后往前恢复被删除的点：
   恢复一个点，cnt++；
   与所有当前存在的邻居合并；
   每次有效合并，cnt--。

4. 每一步保存答案。

5. 将答案逆序输出。
```

一句话总结：

> 并查集不支持删除，但如果删除序列提前知道，就尝试离线逆序，把删除转换为加入。
